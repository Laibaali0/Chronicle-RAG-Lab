# Contributing

This is a learning-oriented engineering repository.

- Keep changes focused and include tests that reproduce failures and exercise boundaries.
- Do not commit private documents, secrets, access tokens, copyrighted model weights, or employer code without permission.
- Use real benchmark outputs and label synthetic fixtures clearly.
- Run `pytest -q` and `bash scripts/smoke.sh` before submitting changes.
- Describe substantive behavior in commit messages; avoid empty commits or backdating activity.
- State when code was developed with AI assistance and review it carefully before relying on it.

A PR should explain the issue, expected behavior, tests, and known limitations. Add a negative test for bugs and a short changelog entry for user-visible changes.
